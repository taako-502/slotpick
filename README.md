# SlotPick

[![CI](https://github.com/taako-502/slotpick/actions/workflows/ci.yml/badge.svg)](https://github.com/taako-502/slotpick/actions/workflows/ci.yml)

Macのカレンダーに同期されているiCloud・Google等の予定から、面談候補と送信用テキストを生成するmacOSアプリです。macOS 14以降、Swift 6対応のXcodeを使用します。

## 実行

`SlotPick.xcodeproj`を開き、`SlotPick`スキーム・`My Mac`で実行してください。ローカル実行用の署名を設定済みです。配布する場合は自分のTeamと署名を設定してください。

初回の「候補を生成」でカレンダーのフルアクセスを求めます。許可が必要ですが、アプリの処理は読み取りのみです。Macの「カレンダー」アプリでアカウントの同期が完了していることを確認してください。

## 初期条件と候補の選び方

- 入力条件は変更のたびにMac内に保存し、ウィンドウを開き直したときやアプリ再起動時に復元します。候補を生成する前の変更や、範囲表示で非表示になっている面談時間も保持します。生成結果は保存せず、復元した条件で再生成します。対象期間は再生成する日の「今日」から数えます。以下は未保存時の初期値です。
- 今日を含む7日間、10:00〜18:00、空き時間の範囲で表示。「面談時間ごと」に切り替えた場合の初期値は60分です。
- 「候補の表示」で、「空き時間の範囲」（初期値）と従来の「面談時間ごと」を切り替えられます。範囲表示は連続した空きを分割せず、例えば13:00〜17:00を1件として表示・コピーします。開始は従来と同じ15分単位の切り上げ、終了は次の予定の余白開始または指定した終了時刻です。
- 範囲表示では面談時間の設定を非表示にし、面談時間に満たない空きも表示します。開始を切り上げた結果、長さがなくなる空きは除外します。「面談時間ごと」に戻すと、前に指定していた面談時間を再び使用します。
- 範囲表示でも、予定前後の余白、候補数、1日最大件数、日付の除外と各日への候補の分散を適用します。
- 既存予定の前後に30分の余白を確保。
- 候補は5件、1日最大2件。最初に各日1件ずつ選び、それでも不足する場合に各日の2件目を選びます。
- 「土日を除外」「日本の祝日・休日を除外」を個別に選べます。初期値は両方オフです。除外しても対象期間の日数は延長しません。
- 全カレンダーが対象。終日予定もブロックし、「空き時間」指定・キャンセル済み予定は除外します。
- 候補開始は15分単位で切り上げ、過去の時刻と重複候補は除きます。候補不足時は得られた件数を表示します。
- 余白は既存予定に適用します。候補は選択肢なので候補間には余白を追加しません。
- Macの現在のタイムゾーンを使用します。送信文には年・曜日・タイムゾーンを含め、日をまたぐ終了には終了日も表示します。

条件変更・カレンダー変更・候補の開始時刻経過・タイムゾーン変更時には、古い結果を消去します。コピー直前にも予定を再取得して候補を照合し、空き時間が変わっていたら再生成を案内します。カレンダーが1つも取得できない場合は設定確認を案内します。

予定の内容は保存・送信しません。文章の送信やカレンダーへの予約登録は行いません。

## 構成

- `Sources/SlotPickCore`: SearchCondition、BusySlot、CandidateSlot、CandidateGenerator、CandidateFormatter。Foundationのみに依存。
- `Sources/SlotPickSupport`: CalendarService、SlotPickModel、クリップボード。権限取得と予定取得を分離し、画面の状態管理もテスト可能にしています。
- `SlotPick`: SwiftUIのアプリと画面。Xcodeも同じローカルSwift Packageを利用します。
- `Tests`: 候補生成・書式・権限・状態遷移・コピー前再確認のテスト。

## 検証

Xcodeでは`SlotPick`スキームで **⌘U**。ターミナルでは次を実行できます。

```sh
swift test
xcodebuild -project SlotPick.xcodeproj -scheme SlotPick -destination 'platform=macOS' test
```

テストは実際のカレンダーやシステムのクリップボードを変更しません。候補の表示切り替え、空き時間の範囲、夏時間、予定の前後の余白、重複・日またぎ、権限待ち中の日付変更、生成後の予定変更、コピー失敗などを検証しています。

実際のiCloud/Google同期とmacOSの権限ダイアログは、初回実行時に確認してください。

## 日本の祝日データ

[内閣府「国民の祝日について」](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)の[公式CSV](https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv)を2026年10月6日に取得し、日付を`JapaneseHolidays.swift`へ加工して同梱しています。1955〜2027年の祝日、振替休日、祝日に挟まれた休日を対象にし、通信や祝日カレンダーの購読なしで除外できます。判定する日付は検索時のタイムゾーンに従います。

祝日除外オンで対象期間がデータの対応年を超える場合は、候補生成を止め、警告アイコン・オレンジ色の枠と背景を付けたバナーで案内します。カレンダー権限を求める前に確認し、「祝日の除外をオフにする」ボタンでも解除できます。新しい年の公式CSVが公開されたら同梱データと対応年を更新してください。除外オフでも、カレンダー上で「予定あり」とされる祝日イベント等と重なる時間は候補になりません。

## GitHubからDMGをリリースする

1. リポジトリの **Actions → Release DMG → Run workflow** を開きます。
2. ブランチを **main** にし、`bump` で `patch` / `minor` / `major` を選びます。
3. **Run workflow** を実行します。完了後、**Releases** の **Assets** から `SlotPick-X.Y.Z.dmg` をダウンロードできます。

最新の正式タグ `vX.Y.Z` とプロジェクトの初期バージョン（現在 `0.1.0`）の大きい方を基準に更新します。初回なら `patch` は `0.1.1`、`minor` は `0.2.0`、`major` は `1.0.0` です。リリース版のアプリ内部のバージョンも同じ値になり、ビルド番号にはActionsの実行番号を使います。プロジェクトファイルへの自動コミットは行わず、リリース履歴はタグで管理します。

ワークフローは次の順序で実行します。

- 実行時のmainのコミットを固定して取得し、次のバージョンを決定。
- リリース処理のテストとmacOSアプリの全テストを実行。
- Apple Silicon・Intel両対応のReleaseビルドを作成。
- DMGを生成し、アプリの署名・内部バージョン・両CPU対応・DMG内の内容を検証。
- `vX.Y.Z` タグと下書きReleaseを作成し、DMGとSHA-256チェックサムを添付。
- 添付を確認してからReleaseを公開。

タグ作成前のテスト・ビルド失敗ではReleaseは作成しません。タグ作成後にアップロード等が失敗したら、同じ実行の **Re-run all jobs** で同じタグ・下書きから再開できます。公開済みReleaseの再実行では既存の配布物を置き換えません。別の **Run workflow** は新しいバージョンを発行する操作です。同時実行は直列化しています。

`GITHUB_TOKEN` の `contents: write` をワークフロー内で要求するので、通常は追加のSecret設定は不要です。組織ポリシーやタグ保護で拒否された場合は、該当ルールを管理者が確認してください。既定ブランチ以外からの実行はエラーにします。通常のpushだけではリリースされません。現在リポジトリは非公開なので、Releaseのダウンロードにもリポジトリへのアクセス権が必要です。

### 署名について

現在発行するのは **ad-hoc署名版** です。Developer ID署名・Appleの公証は未実施なので、インターネットからダウンロードしたアプリはmacOSに警告・ブロックされる場合があります。一般向けのスムーズな配布には、Apple Developer ProgramのDeveloper ID証明書と公証用の認証情報を別途設定する必要があります。

### ローカルでリリース処理を確認する

```sh
python3 -m unittest discover -s scripts/tests -v
# 次のバージョンの表示のみ。タグやReleaseは作成しません。
python3 scripts/release.py plan --bump patch --run-id 1
# 署名・マウント・チェックサム確認を含めてDMGを作成します。
bash scripts/build-dmg.sh 0.1.1 1 /tmp/slotpick-release-assets
```

GitHubの公開操作は手動ワークフローの最後だけで実行します。リリース処理のテストは一時的なローカルGitリポジトリと模擬APIを使用します。

## CIとlint

`CI` ワークフローはmainへのpush、main宛てPull Request、および手動実行に対応します。

- `swift-format --strict` でSwiftコードの整形・スタイルを確認。
- `actionlint` でGitHub Actions設定を検証。
- Bashの構文確認、リリース処理のPythonテストを実行。
- Xcodeでアプリのユニットテストを実行し、結果の `.xcresult` を7日間保存。

CIとローカルの差を抑えるためXcode 26.6を使用します。Swiftの整形ルールは `.swift-format` に保存しています。整形とlintをローカルで実行するには次を使用してください。

```sh
xcrun swift-format format --in-place --recursive Package.swift SlotPick Sources Tests
xcrun swift-format lint --strict --recursive Package.swift SlotPick Sources Tests
```

CIではタグやReleaseを作成しません。リリースは引き続き **Release DMG** から手動で実行します。
